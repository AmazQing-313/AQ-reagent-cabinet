# 实验室材料「入库 / 出库 / 类型统计」系统 · 方案草稿 v0.1

> 状态：草稿，用于对齐范围与技术路线，尚未开工。
> 适用对象：高校课题组、研究所实验室、企业研发实验室（约 5~80 人，1~3 个库房）。
> 目标：把 Excel 台账替换成「扫码即用」的轻量系统，做到**库存查得到、领用记得住、按类型算得清**。

---

## 0. 一句话结论

**先跑通「建档 → 入库 → 扫码出库 → 库存可见 → 月度分类统计」这条最小闭环，再谈审批流和采购联动。**
技术路线优先推荐 **微信小程序 + 云开发（CloudBase）**；如果团队没有开发资源、且不涉及危化品强审批，**先用飞书多维表格 / 简道云搭一版，2 周内上线试点**，跑顺了再决定要不要自研。

原因：这个系统 90% 的失败不是功能不够，而是**录入成本太高、没人愿意用**。扫码 + 手机 3 步出库，是唯一能让大家坚持用的设计。

## 1. 先想清楚的三件事

| # | 问题 | 为什么关键 | 建议答案 |
|---|---|---|---|
| 1 | 只管**消耗性材料**，还是连固定资产一起管？ | 固定资产要折旧报废，逻辑完全不同，混在一起必乱 | **只做消耗品/试剂/耗材**；固定资产另建台账或后续接资产系统 |
| 2 | 需不需要**批次和有效期**？ | 试剂有批号、有效期、存储条件（-20℃/避光）；只记总数则无法做过期追溯，后期补不回来 | **必须做批次级库存**，这是本系统的地基 |
| 3 | 谁每天维护？ | 库管 1 人 vs 全员自助，界面和权限完全不同 | 建议**全员自助登记 + 库管审核关键操作**，否则库管会变成人肉录入机 |

> 最大的坑：**只做「物料 + 数量」，不做「批次」**。三个月后你会发现「这瓶试剂什么时候到期、哪一批、放哪个柜子」全都查不到，只能推倒重来。

## 2. 角色与真实场景走查

### 角色

| 角色 | 典型人 | 权限 |
|---|---|---|
| 实验室管理员 | PI / 秘书 | 全部数据、审批、导出、配置分类、成员管理 |
| 库管 | 研究生 / 专职 | 入库验收、盘点、报废、库存调整 |
| 普通成员 | 学生 / 工程师 | 扫码领用、查看库存、看自己的领用记录 |
| 只读访客 | 合作方 / 审计 | 只读报表 |

### 五个必跑通的场景

1. **采购到货**：快递到货 3 瓶无水乙醇（500mL，批号 A2310，有效期 2027-06），验收入库、贴码、放到「A 栋 302-柜3-上层」。
2. **学生领用**：做实验要领 200mL 乙醇，扫柜子/瓶子上的二维码，选「用途 + 项目」，10 秒完成，库存自动扣减。
3. **月底统计**：PI 想看 10 月各类材料花了多少钱、哪个课题组用得多、哪些快过期。
4. **过期清理**：系统提示 30 天内到期的 5 个批次，库管确认报废并留痕。
5. **盘点**：季末盘点 A 柜，扫码核对，账实差异走调整单，生成差异报表。

如果这 5 个场景都能在手机上一气呵成，系统就成功了 80%。

## 4. 数据模型（核心设计）

### 4.1 关键原则

1. **物料（material）与批次（batch）分离**：物料是"是什么"，批次是"这一瓶"。
2. **库存不是一个字段，而是批次余量之和**：`库存 = Σ batch.qty_left`。
3. **单据不可改，只能红冲**：所有出入库单完成后禁止直接编辑，纠错靠反向单据，保证审计可追溯。
4. **单位双轨**：入库按包装单位（瓶/盒/包），库存与出库按基本单位（mL/g/个），存换算系数。

### 4.2 表结构（12 张核心表）

```

material        物料主数据   id, code, name, category_id, spec, brand, supplier_id,
                            unit_pkg, unit_base, ratio, cas_no, storage_cond,
                            hazard_class, safety_stock, shelf_life_days, is_active
batch           批次        id, material_id, batch_no, qty_in, qty_left,
                            unit_cost, expire_date, location_id, supplier_id,
                            inbound_id, status(在用/耗尽/过期/报废), qr_token
location        库位        id, parent_id, name, type(楼/房间/柜/层/盒)
supplier        供应商      id, name, contact, phone, qualification
inbound_order   入库单      id, no(RK20261026-001), type(采购/调拨/捐赠/退库),
                            supplier_id, biz_date, operator_id, total_amount,
                            invoice_no, status(草稿/待审/完成/作废), remark
inbound_item    入库明细    id, order_id, material_id, batch_no, qty, unit_price,
                            expire_date, location_id, photo
outbound_order  出库单      id, no(CK...), type(领用/报废/调拨/归还),
                            applicant_id, project_id, purpose, biz_date,
```

### 4.3 核心表 SQL 片段（示意）

```sql
-- 批次：全系统的库存真相
CREATE TABLE batch (
  id            VARCHAR(32) PRIMARY KEY,
  material_id   VARCHAR(32) NOT NULL,
  batch_no      VARCHAR(64),
  qty_in        DECIMAL(14,3) NOT NULL,
  qty_left      DECIMAL(14,3) NOT NULL CHECK (qty_left >= 0),
  unit_cost     DECIMAL(14,4) DEFAULT 0,
  expire_date   DATE,
  location_id   VARCHAR(32),
  status        TINYINT DEFAULT 1,   -- 1在用 2耗尽 3过期 4报废
  qr_token      VARCHAR(32) UNIQUE,
  created_at    DATETIME DEFAULT NOW(),
  INDEX idx_mat_exp (material_id, expire_date),
  INDEX idx_exp (expire_date, status)
);

-- 出库明细挂批次，而不是挂物料：这样才能追溯"哪一瓶"
CREATE TABLE outbound_item (
  id          VARCHAR(32) PRIMARY KEY,
  order_id    VARCHAR(32) NOT NULL,
  batch_id    VARCHAR(32) NOT NULL,
  qty         DECIMAL(14,3) NOT NULL,
  unit_cost   DECIMAL(14,4)
);
```

## 5. 业务规则（写进代码前先约定）

| 规则 | 说明 |
|---|---|
| **FEFO 出库** | 默认推荐"最早到期"的批次；允许手动改批次（如已开封的那瓶） |
| **不允许负库存** | 出库前校验 `qty_left >= 出库量`，并发用行锁/事务 |
| **成本口径** | 库存金额 = Σ(qty_left × unit_cost)；采用批次实际成本（简单、可解释），不做移动加权 |
| **单位换算** | 1 瓶 = 500 mL，入库录 2 瓶自动转 1000 mL；出库按 mL |
| **有效期** | 试剂/标准品/培养基必填；普通耗材可空。到期自动置为"过期"并进预警 |
| **状态机** | 草稿 → 待审批 → 已完成 → 已作废；已完成不可改，作废需填原因并回滚库存 |
| **盘点** | 冻结范围 → 扫码录入实盘 → 生成差异 → 审批后生成调整单（不直接改批次） |
| **预警** | 低库存：`qty_left 总和 < safety_stock`；临期：`expire_date - today <= 90 天` |
| **删除** | 一律软删除（`is_active`），历史单据永久保留 |
| **编号** | `RK/CK/PD + yyyyMMdd + 3 位流水`，按日重置 |

## 6. 统计与报表设计（"类型统计"是重点）

### 6.1 六维度 × 六指标

| 维度 | 指标 |
|---|---|
| 时间（月/季/年） | 入库数量、入库金额 |
| 材料分类（两级） | 出库数量、出库金额（消耗） |
| 物料 | 期末库存数量、库存金额 |
| 供应商 | 周转天数、呆滞金额 |
| 项目 / 课题组 | 临期金额、报废金额 |
| 领用人 | 消耗 Top10、人均消耗 |

### 6.2 口径必须写清楚（否则 PI 和财务会对不上）

- **消耗 = 领用出库**；报废、调拨、盘亏**单列**，不计入消耗。
- 统计按**单据完成时间**归期，不按创建时间。
- 金额含税/不含税统一一种，写进说明。
- 周转天数 = 期间平均库存金额 ÷ 期间出库金额 × 天数。
- 呆滞 = 90 天无出库的批次（金额合计）。

### 6.3 首屏图表（建议 4 个）

1. 饼图：本月消耗金额按**一级分类**占比（这就是用户说的"类型统计"）。
2. 柱线组合：近 12 个月入库金额 vs 出库金额。
3. 横条：消耗 Top10 物料。
4. 提醒卡：临期 3 项 / 低库存 2 项 / 呆滞 1 项，点进去直接处理。

> 报表弱是低代码平台和小程序的通病。解法：**统计页只做"看"，明细一律导出 Excel 再加工**，不要在前端做复杂透视。

| 路线 | 上手速度 | 扫码/通知 | 报表能力 | 数据可控 | 年成本（估） | 适合 |
|---|---|---|---|---|---|---|
| A. 飞书多维表格 / 简道云 | ★★★★★（1 周） | 中（可扫码） | 中 | 低（SaaS） | 0~3000 元 | 无开发资源，先验证流程 |
| B. **微信小程序 + 云开发** | ★★★★（2~3 周） | ★★★★★ | 弱（需导出） | 中（腾讯云） | 约 1000~3000 元（含认证 300） | **推荐**：≤50 人、要扫码、无运维 |
| C. Web（Vue/React + PostgreSQL） | ★★★（3~5 周） | 中（H5 调摄像头） | ★★★★★ | 高（可内网） | 1000~5000 元 | 有 IT、要对接财务、数据必须内网 |
| D. 企业微信自建应用 | ★★★ | ★★★★ | 中 | 中 | 同类 B | 已在用企微，免登录+消息推送 |

- 小程序（体验层）+ 云开发数据库与云函数（逻辑层）+ 云函数定时任务（预警推送）+ 导出 Excel（报表层）。

### 出库只要 3 步（硬指标：15 秒内完成）

1. 扫瓶身/柜位二维码 → 自动带出物料、批次、有效期、剩余量。
2. 输数量（默认 1，带 +/- 和常用量快捷按钮）。
3. 选用途/项目 → 提交。成功后给「再来一单」按钮。

### 其他要点

- **标签**：40×30mm，内容 = 物料名 + 规格 + 批号 + 有效期 + 二维码；二维码用短链 `https://x.cn/b/{token}`，扫不出也能手输 6 位码兜底。
- **盘点**：支持离线，先存本地再同步，避免库房没信号。
- **防呆**：数量超库存直接拦；有效期早于今天不允许入库；危化品出库强制填用途。

## 10. 常见坑（前人踩过的）

1. **不做批次** → 无法追溯有效期与来源，后期无法补救。（最致命）
2. **分类一开始太细**（分到 4 级 30 类）→ 录入崩溃、大家乱填。**先两级 + 允许"其他"**。
3. **单位不统一**（有的录"瓶"有的录"mL"）→ 库存永远对不上。**强制基本单位 + 换算系数**。
4. **没有扫码** → 纯手输，三天后没人用。
5. **一上来做审批流/财务对接** → 拖半年上不了线。
6. **前端直接改库存数字** → 无单据、无日志，出事查不清。**库存只能由单据驱动**。
7. **权限过粗**（所有人都是管理员）→ 误删误改，数据报废。
8. **历史 Excel 直接导入** → 脏数据污染。先清洗：去重、补单位、统一分类，导入做幂等 upsert。
9. **忽略危化品合规** → 若涉及易制毒/易制爆，需购买备案、双人双锁、专柜台账，最好从第一天就按危化品单独标记。

2. **合规**：是否涉及危化品、易制毒/易制爆、生物样本、放射性？要不要审批和双人复核？
3. **平台**：团队习惯微信、企业微信还是钉钉？有没有内网/数据不出校的要求？
4. **资源**：有没有人能写代码（自己/学生/外包）？还是必须用低代码平台？

> 回答这 4 个问题后，我可以把本方案收敛成一份**可执行的 MVP 需求文档 + 接口/表结构定稿 + 页面清单**，或者直接搭一个可点的小程序原型。
